# 应用状态屏蔽 · AppStateShield

一个 Vector 模块，按应用屏蔽截图、VPN、网络代理、开发者选项、USB/无线调试及 SELinux 状态，并为指定应用伪装设备信息。当前模块与验证器版本为 **0.4.13**。保留一个“应用状态验证器”，用来观察应用实际读取结果。

0.4.13 为设备标识、机型与系统、位置、其他环境统一提供分类总开关，分类标题显示“已开启 / 已关闭”。网络与基站使用“已关闭 / 模拟 SIM 卡 / 模拟无 SIM 卡”三档，标题显示当前档位。新档案各分类默认关闭；字段必须经过机器总开关、分类控制和自己的开关才能使用保存值。所有分类的字段都有行内独立开关，模拟 SIM 不再强制选中蜂窝字段。关闭分类保留参数和单项选择，刷新及填写预设不会自动打开分类。详见 [分类开关说明](docs/CATEGORY-GATES-0.4.13.md)。

本轮完成 13 项专用模拟器检查和每个字段的三级组合检查，原始结果、已知无法验证项及环境恢复记录见 [0.4.13 测试报告](verification/CATEGORY-GATES-0.4.13-REPORT.md)。两个 APK 已在 vivo V2419A 完成覆盖安装，文件哈希、版本、原配置、授权和 Vector 作用域已核对；此次安装未追加真机功能测试。下载见 [v0.4.13 Release](https://github.com/lwtdzh/AndroidAppPermissionControl/releases/tag/v0.4.13)。

0.4.12 的验证器打开后自动检查系统环境，在首页显示通过、发现信号、无法确认和参考信息的数量；“展开检查详情”显示逐项读数，“重新检查环境”重新读取。检查包括 Su/Busybox/Root 文件的 Java、libc 和直接 syscall 读取，已知注入库的 maps/加载器枚举，Xposed 类与可见模块、构建及 DLKM 属性、VPN/代理/调试/SELinux，以及新生成的 AndroidKeyStore 证明。证明分别展示 Google 根匹配、签名/有效期、随机挑战、安全级别和启动字段，完成后删除本次临时密钥。日志和私有 JSON 同时保存结果；检查不执行 su、不修改系统模式、不联网、不申请设备 ID 证明。详见 [环境检测能力与结果解释](docs/VERIFIER-ENVIRONMENT.md)。

## 尚不能修复的环境检测项

下表来自 0.4.11 的 Native Detector、Ruru、Key Attestation 模拟器对照。“不能修复”指当前进程内模块尚无经过实际验证的修复；每项都保留具体环境和原因，供后续 AI Agent 判断。

| 检测项目 | 已验证的现象 | 当前不能修复的原因 |
|---|---|---|
| Native Detector：Found Injection | 进入 Vector 作用域后出现，空模块也出现；详情和真实进程映射均含 Vector/ZygiskNext 库。 | 框架库已实际加载。隐藏模块安装列表不改变内存映射；卸载库会破坏注入。具体枚举算法尚未定位，尚无保持模块正常运行的已验证隐藏方案。 |
| Key：Unknown root certificate | 原 AOSP 镜像及未注入对照使用 Google Test LLC / Droid Unregistered Device CA。 | 模块没有受信任 CA 的签发能力。修改证明会破坏签名，自签证书不能取得原受信任根的认可。 |
| Attestation security level = Software | 模拟器证明安全级别为 Software。 | 实际证明由软件密钥服务生成；修改机型、属性或应用读数不能建立 TEE/StrongBox 硬件隔离。 |
| Keymaster / KeyMint security level = Software | 模拟器密钥管理实现也为 Software；这是独立于证明安全级别的另一个字段。 | 进程 Hook 不能把软件 KeyMint 转为硬件密钥管理实现。需要实际支持相应能力的设备与证明配置。 |
| deviceLocked = false | 原模拟器对照即为 false。 | 模块不修改真实启动链，无法将签名证明中的锁定状态改为 true 并保留原签名。真机是否能安全重新上锁取决于设备和镜像。 |
| verifiedBootState = Unverified | 原模拟器对照即为 Unverified。 | 填写系统属性不能建立 Android Verified Boot（AVB）验证链；需要实际启动环境完成验证，再由密钥服务生成证明。 |
| verifiedBootKey 全零 | 模拟器原证明未提供有效的生产启动验证密钥。 | 任填一个非零值不能建立它与实际启动密钥、镜像和证明签名的关系；模块不拥有相应签发能力。 |
| verifiedBootHash 全零 | 模拟器原证明未提供有效的受验证镜像摘要。 | 模块无法生成与实际受验证镜像对应的 VBMeta 摘要并让原证明链签名；替换显示字符串不能改变启动验证。 |

后两项是证明字段，原检测页没有为它们分别显示顶部告警。[逐项证据与完整解释](docs/DETECTOR-LIMITATIONS-0.4.11.md) 保留原报告、APK 和环境归属。

| 另列的无法验证项 | 当前限制 |
|---|---|
| 设备 ID / 设备属性证明 | 该模拟器缺少 android.software.device_id_attestation 功能，检测菜单没有相应入口。模块能减少身份字段请求，无法补出缺失的硬件证明能力，也不能让合成身份获得真实硬件认可。 |

0.4.12 在 vivo V2419A 上实际读到的证明与 KeyMint 安全级别均为 TrustedEnvironment（TEE），因此表中的 Software 结论只适用于原模拟器。真机结果记录在 [安装与环境检查记录](verification/vivo-environment-0.4.12-installed.json)。新检测器未匹配已收录的 Google 根时，也可能面对厂商根；未知根、权限拒绝、只匹配已知库路径和未检查在线吊销须分别说明。后续 Agent 应保留这些限制及 [检测能力说明](docs/VERIFIER-ENVIRONMENT.md)，按目标环境重新验证。

## 版本记录

机型伪装补齐 DLKM 分区的构建元数据，从选中指纹派生，修复 Native Detector 的 vendor_dlkm test-keys 提示。VPN 的 getNetworkInfo 查询保留网络对象，并返回未连接状态，避免空结果触发 Ruru 的可疑提示；实际 VPN 连接保持运行。[三款工具实测报告](verification/DETECTOR-0.4.11-REPORT.md) 与 [尚未解决的逐项原因](docs/DETECTOR-LIMITATIONS-0.4.11.md) 分别说明真实检测结果和当前限制。

0.4.9 移除顶部“更新随机标识”。设备标识、网络与基站、机型与系统分别在分类内提供统一刷新按钮，每个按钮只更新本分类的参数；单项编辑和刷新继续保留。

0.4.8 将小米 14、vivo X200 Pro mini 的机型预设选择放进“机型与系统”，展开分类后才能看到。选择预设只更新机型、系统和屏幕参数，保留设备标识、网络、位置、其他环境字段及各总开关。

0.4.6 为选中的只读设备属性补充 find、枚举与缓存对象适配，让属性文本与对象头部、serial 一致。设备层与现有 debug/SELinux 读取层共用指针映射；旧缓存保留旧伪装值，重新查找读取当前档案。[对象实现与限制](docs/PROPERTY-OBJECTS-0.4.6.md)。直接读取系统属性区、映射来源检查和未注入进程仍未完整覆盖。

0.4.5 同步指纹的编译编号/类型/标签，修正可选容量与剩余量之间的关系，并对验证器状态接口校验包名和签名。设备伪装从未开启时不安装设备 Java Hook。设置页会提示指纹字段矛盾、跨 Android 大版本、隐藏传感器和 SIM 对一键登录的影响。[调研后修复说明](docs/ENVIRONMENT-0.4.5.md)。这些修复不能保证商业应用登录或隐藏任意检测方式。

0.4.4 修复旧 native 属性接口：长属性名按完整名称匹配预设，超长只读指纹在旧 get/read 中返回兼容提示，Java 和 callback 返回完整预设值。替换时清空整个旧接口值缓冲区，避免本机指纹尾部残留。机器或字段关闭后恢复原值。[修复和测试说明](docs/PROPERTY-READ-0.4.4.md)。

0.4.2 的位置分类增加离线省市区选择，一次填写经纬度和精度，也可逐项修改。当时网络模式默认无 SIM；0.4.13 的新档案改为默认关闭，网络参数按独立字段开关生效。网络、机型与系统、设备标识的分类内刷新继续保留。[位置与网络原始实现](docs/LOCATION-0.4.2.md)。

主模块默认不显示桌面图标。从 Vector 的模块页打开设置，开启“显示应用图标”后也可从桌面进入，并供分身工具识别。能否分身仍取决于工具支持。图标开关按 Android 用户保存，升级后保留选择。Vector 决定作用域；设置页为作用域内的应用选择屏蔽方法。未定制应用默认全部开启，包括以后新增的方法。

验证器首页增加状态信息条，每 2 秒刷新 VPN、网络代理、开发者选项、USB/无线调试和 SELinux。它展示本应用读到的值；注入模块后，读数可能经过屏蔽。读取失败显示“无法读取”。传统日志、读取检查和来源选择继续保留。

图标、状态条和 vivo 安装的实际结果见 [0.3.1 测试记录](verification/STATUS-UI-0.3.1.md)。SELinux 文件不可读且 Java API 返回 false 时显示“模式无法确认”，避免把读取失败当成宽容模式。

“本次打开”的截图次数与日志的信号条数分别统计：按文件路径、图片 ID 和 2 秒内的多入口信号合并估算；快速连拍、延迟通知或没有身份的信号仍可能误差。仅检测首页前台期间计数，旋转、返回、清空日志和重启监听保留次数；结束页面重新打开或冷启动后清零。0 次需要结合权限和真实截图基线判断。

## 使用

1. 安装 AppStateShield APK，在 Vector 启用模块并选择作用域。
2. 默认即可使用。需要单独设置时，从 Vector 打开模块设置，点“添加应用”，选择应用，调整开关并保存。
3. 强行停止并重新打开目标应用，让新配置生效。
4. 删除定制条目恢复全部开启。定制列表不改变 Vector 作用域。

六个开关独立生效。SELinux 开启时，目标应用的 Java API、libselinux 状态函数和常见 enforce 文件读取返回强制执行状态（Enforcing / 1）；系统实际模式保持原样。关闭后恢复真实读取。旧定制只保存已关闭的方法，升级后 SELinux 默认开启。

## 机器伪装

机器伪装默认关闭，需要为每个应用单独开启。原有六项状态屏蔽的默认规则不变。进入应用详情，点“配置机器伪装”：首次开启生成小米 14 档案，可更换为 vivo X200 Pro mini，也可手工编辑。小米预设来自国际版 HyperOS 2.0.201.0 固件；vivo 预设来自本机 Android 16 实测。机型、代号、主板、硬件、系统版本和指纹使用固定真实数据；各分区保留固件原有的不同名称。Find X9s 已移除。IMEI、MAC 等标识仍独立生成，不复用本机个人标识。[预设来源和字段说明](docs/MODEL-PRESETS-0.4.3.md)。

47 个字段按设备标识、网络与基站、机型与系统、位置、其他环境分组，默认收起，可搜索。每个分类都有总控制，标题显示当前状态；屏幕参数属于“机型与系统”。机器总开关、分类控制和单项开关全部允许时，已选参数才生效。每项都有独立开关，也能手工填写或从预设填入；IMEI、OAID、序列号、MAC 等还提供随机刷新。行内刷新选中对应字段，统一刷新只填写并选择当前分类，均保留分类总控制。新档案和旧文档中缺失的控制默认关闭；原来明确保存的机型、位置开关及网络档位保留。关闭分类保留填写值和单项选择，更换预设不自动开启分类。随机值保存后固定保留，不会在每次读取时变化。IMEI 有格式和校验位检查，两个卡槽各自生成。

保存后，目标进程通过通知和前台两秒轮询更新档案，返回页面时立即刷新。重复调用的系统接口可跟随更新；应用自身缓存、ART 内联或启动时判断需要强行停止后重开。关闭主开关保留档案，删除定制恢复机器伪装关闭和原有六项屏蔽默认开启。修改总内存、容量、语言、时区、隐藏传感器和 DRM ID 需另行勾选。

验证器首页直接显示双卡 IMEI、Android ID、OAID、序列号和机型，每 2 秒实际读取；点击“查看全部 47 项”进入标识优先的详情页，可搜索 MAC、SIM、基站、位置、屏幕等全部字段，并查看 Java/native 额外入口、时间、PID 和变化。旧设备状态页也提供同样摘要。后台暂停，切换页面串行采样。原始调试信息可展开，传统日志继续保留。

Android 10+ 的真实 IMEI 等常需特权或运营商权限，无法读取时显示具体原因；系统隐私占位 MAC 也单独标明。检测器不把配置值当作检测结果。厂商 OAID 服务在 AOSP 模拟器上通常不存在，不能用空值确认伪装成功；debug A/B 的厂商 SDK 形状只是测试夹具，正式 APK 不包含它们。原需求与漏项对照见[0.4.1 复盘](docs/REQUIREMENT-AUDIT-0.4.1.md)。

电话接口使用同包、同 UID 的短生命周期辅助进程，结果注明入口并附辅助 PID；其余接口在检测页进程读取。电话服务不回复时显示超时并结束辅助进程，避免卡住的 Binder 请求导致后台检测页被系统结束。

现有拦截涉及常见 Java 接口、明确的厂商标识接口和 native 属性、网卡读取。内核直读、任意 Binder 请求、硬件认证、应用私有缓存、公网 IP、账号和服务端关联仍可能暴露真实信息。具体入口和限制见[逐项说明](docs/DEVICE-SPOOFING.md)，新增测试见[机器伪装测试计划](docs/DEVICE-TEST-MATRIX.md)。

SELinux 不修改系统权限或进程安全上下文。直接内核系统调用、未注入的 shell 子进程、其他挂载位置及保留的加固入口仍可能读到真实模式；读取原本失败时不会伪造文件成功。具体路径见[SELinux 验证记录](verification/SELINUX-0.3.0.md)。其他应用的自定义、内核或服务端检测也不保证全部覆盖。

0.2.1 修复了 vivo 上动卡空间开启截图屏蔽后启动卡住的问题。ARM64 原生层会保留函数入口已有的外部跳转，避免覆盖应用加固库的 Hook。这些入口的原生读取无法由本模块完整屏蔽；Java 层和其余成功安装的原生 Hook 继续生效。验证范围和限制见[兼容性记录](verification/VIVO-COMPATIBILITY-0.2.1.md)。

## 工程

```text
app/             整合模块、设置页、策略服务及 native hooks
verifier/        保留验证器、截图日志、低层文件读取和设备状态检查
scripts/         根工程构建、签名、专用模拟器与测试执行
docs/            整合设计、逐步人工测试手册
shared/          共用设备字段目录、格式校验与 native 符号工具
verification/    当前验证报告与 legacy 历史记录
gradle/          全工程共用 wrapper
```

`:app` 包名为 `io.github.lwtdzh.appstateshield`。`:verifier` 保留 `io.github.lwtdzh.screenshotdetector` 和原签名。sampleA/sampleB flavors 只供多应用隔离测试，正式交付不需要安装。

## 构建

JDK17、Android SDK36、NDK29.0.14206865、CMake3.22.1：

```sh
./scripts/build-all.sh
python3 scripts/sign-apk.py app/build/outputs/apk/release/app-release-unsigned.apk /path/to/AppStateShield.apk
python3 scripts/sign-apk.py verifier/build/outputs/apk/primary/release/verifier-primary-release-unsigned.apk /path/to/AppStateVerifier.apk
```

主模块 minSdk27/targetSdk36。验证器 minSdk28/targetSdk28，保留旧文件权限以比较 JNI/NIO 读取；这是侧载的诊断应用，未面向 Play 发布。官方截图日志页要求 API34，较低版本打开设备状态检查。
