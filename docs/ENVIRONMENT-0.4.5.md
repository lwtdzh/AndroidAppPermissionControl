# 0.4.5：设备环境调研后的修复

详细调研已在修改代码前保存至交付目录 AppStateShield-environment-research-20261114/Android设备环境检测调研.md。覆盖 32 类检测入口，包括国产安全 SDK、root/注入、原始系统属性、隔离进程、跨硬件一致性及服务端证明；源码固定到提交并附文件 SHA-256。Momo 没有取得可核对的完整源码，报告没有把其他检测器的算法当成 Momo 源码。

本版本修复实际代码里可验证的六项问题，不承诺淘宝/拼多多登录成功。没有取得这两款应用的失败请求和服务器判定，无法把此次登录失败归因到某一个检测函数。

| 修改前 | 修改后 |
|---|---|
| 指纹替换，Build.ID/TYPE/TAGS 仍是宿主值 | 从完整指纹推导；各分区保留自己的真实指纹和编译编号 |
| 任何应用自带同名 ModuleStatus 类就可能获得模块上报 | 同时检查固定包名、加载包名与固定发布签名 |
| 从未开启机器伪装也安装设备 Java Hook | 首次开启时才安装，通知和前台轮询保留 |
| 可选改总容量，原剩余容量可能大于总量 | 按实际占比同步 MemoryInfo、数据分区 StatFs 及普通 File 容量 |
| 有关指纹、Android 版本、传感器和 SIM 的矛盾藏在长说明里 | 设置页读取草稿展示具体提示，允许保存或丢弃 |
| 检测器只显示总内存/总空间，没有对应关系 | 新增实际读取的元数据、类型化属性、总量/剩余量/块数 |

指纹非标准格式时保留用户输入，不臆造 ID/TYPE/TAGS；显示格式提醒。关联信息随指纹字段开关恢复，其他字段仍由各自选项控制。真实 API 等级、内核、HAL、GPU、可信硬件证明不随预设改变。跨 Android 大版本会显示提示。

容量适配按文件系统设备号限定到数据分区。系统分区和原始读取失败保留；只改变目标进程看到的数值，不修改存储、RAM 或系统模式。首次开启前已缓存的 StatFs 对象和应用缓存值仍需冷启动。可用量与阈值按相同占比改变，低内存状态保留。

验证器状态标记表示模块上报的配置。实际 API 结果另外读取；“模块已加载”不证明所有环境入口都已替换。签名反例会保留实际设备适配，同时确认状态类没有被接管，以排除“根本没注入”的假阳性。

## 对调研中每类入口的处理

| 编号 | 结果与下一步 |
|---|---|
| D01、D02 | 本次修复编译元数据，保留真实分区差异；其他自定义字段不自动覆盖 |
| D03 | 本次增加 Java 类型化属性检查和 Java/native 元数据对照；所有 JNI/OEM 接口不作保证 |
| D03 实际发现 | 专用模拟器 getInt/getLong 对被替换的密度仍返回缺省值 -17；已增加选定属性的 getInt/getLong/getBoolean 适配并保留调用方默认值与整数范围 |
| D04 | 0.4.4 已修旧 get/read 名称、长值与缓冲区；本次在新版本抽查指纹入口，不重跑未变化的 sanitizer 矩阵 |
| D05、D06 | 原始属性区及 serial 未虚拟化。需要完整虚拟属性对象与一致的并发更新；只篡改单个长度字段可能损坏 libc 读取 |
| D07、D08 | exec 子进程、任意 ARM64 SVC 未覆盖，不能通过增加几个 libc Hook 宣布修复 |
| D09 | 保留既有 Provider/Parcel 适配；未知 Binder/OEM 服务不能靠猜字段扩展 |
| D10 | 本次增加跨 Android 大版本提示，保留实际 SDK_INT，避免应用调用不存在的 API |
| D11、D12、D13 | root、挂载来源、TracerPid/线程/管道属于不同可观察面；本模块六项状态屏蔽不等于全量 root 隐藏 |
| D14 | 本次减少从未启用时的设备 Java Hook；Vector 自身类、映射和对象仍可见 |
| D15、D16、D17 | ART 全局引用、代码入口与磁盘校验需要框架/运行时支持。本次未用改名或过滤字符串冒充修复 |
| D18、D19 | Vector 2.2 源码排除 AppZygote/隔离 UID；需要框架可靠传递父应用身份及更早注入。Provider 的 UID 校验不能随意放开 |
| D20 | 本次固定包名与签名校验，覆盖正例、同名类错误包、允许包错误签名 |
| D21 | CPU/GPU/相机/驱动和真实 SoC 不由 Build 字段改变；预设完整硬件互换尚未实现 |
| D22 | 默认保留传感器，本次对选择隐藏者说明功能和异常影响 |
| D23 | 本次修复容量关系并增加 StatFs/File/MemoryInfo 实际对照；内核 statfs 与 proc 内存仍不变 |
| D24 | 保留既有屏幕适配和布局说明，真实物理渲染未替换 |
| D25 | 既有 IMEI 生成保持格式校验；不把 Luhn 合法误写为厂商已分配 TAC，不借用他人标识 |
| D26 | 保留已有标识接口；原始 DRM/OEM 服务及历史缓存未全部覆盖 |
| D27 | SIM/基站成组适配保留；本次说明模拟状态不创建真实运营商一键登录通道 |
| D28、D29 | 既有 Wi-Fi/位置适配保留；公网 IP、热点数据库、实际运动轨迹不随静态档案改变 |
| D30 | 不篡改真实用户路径；工作资料和双开是合法环境，检测器的可疑标签不能直接作为故障结论 |
| D31 | 不制造 TEE 证书或服务端接受的硬件证明 |
| D32 | 历史账号/行为/网络和风险 Token 的服务端关联不由本地模块消除 |

## 验证安排

新增 JVM 检查见 shared/test/EnvironmentProfileTest.java，检查完整/非标准指纹、自定义值、字段和主开关、真实分区推导、提示及数量关系。模拟器定向脚本执行从未开启、真实 UI 保存/丢弃、同进程开启/更新/关闭、类型化属性、容量对照、共享 debug/SELinux 入口和身份反例。

0.4.4 完整 64 组合和 sanitizer 结果保留原 APK 归属。没有修改六项 Methods、策略语义、共享 native 过滤实现或方法间组合，本次仅补受影响的集成观察，不把历史结果改标为 0.4.5 实测。构建、定向检查结果、失败与恢复记录见交付测试报告和 JSON。
