# 机器伪装的分类总开关

0.4.13 把分类控制统一到每个分组。进入机器伪装设置后，分类标题始终显示当前状态；展开后修改分类控制，再分别选择字段。每个字段都有行内开关，编辑对话框中的选择与行内开关同步。

| 分类 | 保存的总控制 | 新档案默认状态 |
|---|---|---|
| 设备标识 | idsEnabled | 已关闭 |
| 网络与基站 | networkMode：off / simulate / no_sim | 已关闭 |
| 机型与系统 | modelEnabled | 已关闭 |
| 位置 | locationEnabled | 已关闭 |
| 其他环境 | environmentEnabled | 已关闭 |

已保存参数必须同时满足机器伪装总开关、分类控制和该字段的单项开关才会使用。顶部显示已选字段数量和当前生效数量。关闭分类保留数值和单项选择，之后再次开启可继续使用。填写预设、单项随机值和分类统一刷新只准备参数与字段选择，不自动打开分类。

## 2026-11-19 新档案默认字段选择

新档案仍保持所有分类总开关关闭，但字段默认选择调整为：设备标识 9/10（继续排除 `drm_id`）、网络与基站 15/15、机型与系统 13/13、位置 3/3、其他环境 6/6，共 46/47 个字段。已准备好的参数只有在机器总开关、对应分类和单项字段都允许时才生效，因此新档案刚创建时的当前生效字段仍为 0。此调整只影响 `DeviceProfile.preset()` 创建的新档案；解析已有档案时保留原 `selected`，不做迁移、补选或自动改写。

网络的标题显示“已关闭”“模拟 SIM 卡”或“模拟无 SIM 卡”。

- 已关闭：网络和 SIM 读取沿用系统原值或原异常，Wi-Fi/蓝牙参数也不应用。
- 模拟 SIM 卡：提供虚拟有卡/注册状态；保存的运营商、SIM、基站及 Wi-Fi/蓝牙参数分别遵守单项选择，不强制开启蜂窝字段。
- 模拟无 SIM 卡：提供无卡、无订阅、无基站状态，SIM/运营商/基站的保存参数不使用；Wi-Fi和蓝牙仍由自己的单项开关控制。

三档控制 SIM 状态，字段开关控制保存参数的覆盖。关闭字段后，普通接口继续原有读取；模式生成的虚拟对象保留未选字段的默认空值或未知值，不再填入未启用的保存值，也不填入临时编造的数值。同步读取、异步回调和 Parcel 使用同一规则。部分选择可能不构成完整的运营商参数包，统一刷新可准备匹配参数，但不会替用户改变分类总控制。

旧文档中缺失的 idsEnabled/environmentEnabled 默认 false，数值与单项选择仍保留；已明确保存的 modelEnabled、locationEnabled 和 networkMode 保留。缺失的网络模式默认 off。未知字段继续保存，但没有目录中的分类元数据就不能实际生效。

实现入口为 DeviceSettingsActivity → DeviceProfile.groupEnabled/get → DeviceRuntime/DeviceHooks。静态 Build、Java/native 属性、标识、内存/容量、传感器、模块列表及证明身份字段都使用同一个 get 结果；验证器分类标题依据模块快照显示实际状态。

本次只改变机器档案的分类门控及相关虚拟对象，不改变六项状态屏蔽策略。验证包括每个字段三层组合、文档迁移、真实 UI 保存/取消/旋转、分类刷新、网络三档及同 PID 的启用/关闭还原。四 ABI 编译和 API36 ARM64 运行分别记录；旧 64 组合保留原版本结果。发布文件见 [v0.4.13 Release](https://github.com/lwtdzh/AndroidAppPermissionControl/releases/tag/v0.4.13)。

专用模拟器执行器为 scripts/category-gates-test.py。capture 在模拟器停止时只保存一次完整原磁盘；ui 通过主设置页进入机器伪装编辑器，执行默认标题、分类与单项开关、保存、旋转、丢弃和刷新；runtime 用原子配置夹具核对分类关闭基线、同 PID 启用/更新/关闭，以及网络完整/部分/空字段的同步、异步和 Parcel 结果；restore 停止模拟器并恢复原磁盘，逐文件比较哈希和权限。已通过用例仅在相同最终 APK 下保留；失败记录和每次耗时写入 verification/category-gates-0.4.13-results.json。
