# 测试范围、结果复用与停止规则

本规则决定 TEST-MANUAL 和 DEVICE-TEST-MATRIX 中哪些步骤需要执行。两份手册保留完整用例目录，不要求每次修改都从头跑完。修改测试文档、报告或打包脚本，也不自动触发应用重建和模拟器测试。

## 修改前先确定要重跑什么

每次修改用一段话记录：修改了哪些文件、会影响哪些行为、需要执行哪些用例、哪些已有结果可以复用。根据实际调用关系判断，不能仅凭 APK 哈希变化把所有结果作废。

| 修改内容 | 本次需要执行 | 通常可以复用 |
|---|---|---|
| 文档、报告排版、交付 ZIP 或校验文件 | 链接、内容、ZIP 和文件哈希检查 | 应用运行、UI 和 64 组合结果 |
| 设置页文字、布局、搜索或草稿处理 | 受影响的保存/取消、旋转、字段编辑及截图；保存逻辑改变时核对一个实际读取 | 未改变的读取入口和六项屏蔽组合 |
| 字段格式、随机生成或机型预设 | 对应 JVM 检查、受影响字段的保存与实际读取；格式或生成逻辑未改的字段无需重复 | 其他字段、旧屏蔽和无关界面操作 |
| 检测器电话读取、辅助进程或超时处理 | 真实未伪装读取、错误显示、配置版本、前后台与同 PID 返回；核对启用后的对应读数 | 未改变的设置操作和旧屏蔽组合；需确认其检测入口没有变化 |
| 配置通知、轮询或生命周期 | 首次开启、同进程更新、后台停止/返回，以及受影响字段还原 | 无关预设、随机值格式和布局 |
| 单个读取适配器，例如 OAID、定位、屏幕 | 该入口的开启/更新/关闭、原值或原错误、普通操作对照及相关对象/回调 | 无关适配器；厂商夹具仍单独标注 |
| 策略默认值、跨应用隔离、注入入口、共享 native Hook 或方法间组合 | 对应权限/生命周期/原生对照；影响六项组合时执行完整 64 组合 | 经过确认未受影响的纯字段格式或界面用例 |

不能确认影响范围时，先读调用链或做小规模对照。只有发现相关影响才扩大测试；不要直接把“不确定”变成全量重跑。

## 完整 64 组合何时执行

新建六项组合测试基线、首次引入机器伪装与旧屏蔽联测，或修改策略语义、共享 native Hook、跨方法交互时，执行完整 64 组合。开发中的每个小修复先定向复测，相关修改稳定后再完成这一轮。

检测器展示、单个字段、预设、文档或打包变化，不单独触发 64 组合。发布时仍核对最终 APK 的安装、签名、版本、注入、启用/更新/关闭和普通操作；未修改的组合行为可以使用经审阅的已有基线。

中断后保留已通过结果，从剩余组合继续。只有与本次修复有关的已通过组合才重跑；不得为保持执行顺序而重新执行前面的组合。

## UI 操作与批量配置分开

保存、取消、丢弃、输入校验、搜索、预设选择和旋转保留草稿必须走真实 UI。修改了这些交互时，执行受影响的代表性步骤。

64 个配置组合和 46 个字段还原，主要检查配置加载后的实际行为。完成代表性 UI 保存核对后，可以在专用模拟器中由测试脚本批量设置有效配置，继续核对实际加载版本、字段值、异常、注入状态和普通操作。不要让每个组合都重复搜索、滚动和导出完整 UI。

批量设置必须保留未知配置项和其他应用配置，保存原档案，并恢复它；避免与应用内存中的旧配置互相覆盖。机器档案更新后核对 revision 和同 PID 读取，旧六项策略仍按冷启动生效。禁止增加正式 APK 的导出写接口，禁止在未授权真机上直接写配置。

全部字段关闭仍须逐项比较 46 个字段的原值/原错误、Java/native 属性，并核对主开关保持开启和 PID 不变。改变的是配置方式，断言不减少。正常场景、原生所有权、真实截图及真实权限基线也不能由空值或合成夹具替代。

## 复用结果需要哪些证据

历史记录保持原 APK 哈希、实际环境、用例、观察结果和失败记录。报告分别标明“本次执行”和“复用已有验证”；不能把旧记录的哈希替换成新哈希，也不能声称旧 APK 的全部运行结果直接来自新 APK。

复用时记录以下信息：

- 原报告和具体用例，以及原 APK SHA-256。
- 本次 APK SHA-256、相关源码或构建输入的对照。
- 修改文件与调用关系，为什么不影响该项检查。
- 平台、ABI、Vector 和真实基线是否仍适用；检测方法和断言是否改变。
- 本次执行的相关启动/集成对照，以及仍未验证的部分。

源文件或环境对照缺失、检测逻辑改变、旧结果失败，或修复确实影响该项时，不能复用。APK 哈希用于准确追溯交付物；重跑范围依据行为影响判断。最终 APK 的签名、ABI、调试夹具排除、文件校验和最后一次环境恢复记录必须是本次数据。

## 时间记录和停止条件

执行前列出用例数量及预计耗时，执行中记录每个用例开始、结束和耗时，报告已完成/剩余数量。定向阶段超过 5 分钟、完整模拟器联测超过 20 分钟时，停止继续追加用例并检查耗时来源；这是执行预算，不是把未完成项改成通过的期限。确需超过预算的项目说明实际等待原因，并保留已完成项。

同一失败没有新修复或新诊断证据时，不连续重试超过两次。先保存失败快照并定位原因。已有真实基线无法建立时标明受限，不通过反复重启等待一次偶然成功。

通过所选步骤后停止该阶段。不因为报告格式变化、准备打包或“再确认一次”而重复应用测试。新修改或新失败出现时，重新按修改内容选择步骤。

原快照只保存一次且禁止覆盖；中断后不要恢复、重新准备、重新随机整份档案，再把已有结果全部作废。最终结束或明确取消测试时统一恢复环境；临时暂停时记录当前状态和恢复入口。

## 执行器如何落实本规则

scripts/test_device.py 的批量配置只接受 emulator-5584 / ScreenshotShield_API36 和三个测试包。先结束模块自身进程，保留完整 XML、其他应用和未知方法 ID，经 UID/权限/SELinux 标签处理后原子替换，并读回比较；不结束检测页进程。机器档案 revision 递增，固定值不重新随机。

scripts/selinux-test.py 的 matrix 保留代表性真实 UI 保存证明，其余组合批量设置策略，每个组合仍冷启动读取并执行原有断言。scripts/machine-test.py 的 D06-all-fields-off 批量切换总开关、空字段集合和原档案，继续逐项比较 46 个原值/原错误、Java/native 属性与同 PID。手工 IMEI 等设置交互继续走 UI。

中断续跑先核对已安装 APK 字节、真实 VPN/USB 基线和原快照；模式基线和相同 APK 的已通过组合原样保留。矩阵还核对机器档案 revision。每个新执行条目记录开始时间和耗时；64 组合执行超过 20 分钟时保留结果并停止追加。regression 的 --case 已传给嵌套执行器，可选择 M6-000111 等内部用例；定向执行保留夹具供后续续跑。

scripts/build-all.sh 成功后生成 verification/build-inputs.json，记录构建时源码及未签名 APK 内容指纹。后续用例只有在当前源码、正式 APK 内容与该记录一致时才绑定它。历史用例没有构建时源码记录，不能事后补写记录并升级为新 APK 的证明。本轮旧哈希记录不用于跳过剩余检查。

跨 APK 复用通过 scripts/test_evidence.py 校验。报告的 reuse 条目须固定原报告/源码 SHA-256、原始与本次 APK、变更文件、审阅人、原因及本次开启/更新/关闭的集成记录。读取入口、Hook、Schema、Manifest、构建输入和执行器断言须相同；仅 M6 和原生文件用例允许在明确审阅保存契约后排除两个设置 Activity 文件。其他布局、预设或读取变更需执行相应用例。本次 APK 的签名、ABI 和最终恢复不复用。

集成记录在本次开启/更新/关闭三项用例及真实未注入的 VPN/USB/SELinux 基线完成且有源码绑定后，用 python3 scripts/test_evidence.py --integration 生成；生成器保留按 SHA-256 命名的观察副本。原报告和构建输入也须保留为历史副本，再填写 reuse 条目。打包与收尾调用同一校验器，报告区分实际验证与复用，不替换原哈希。缺少证明会拒绝交付，无无条件跳过开关。scripts/check-test-executor.py 用离线夹具检查配置保留，以及源码变化、环境变化、原始绑定缺失、基线改变时的拒绝行为；不代替应用运行测试。

定向执行示例（已有快照、安装和所需档案时使用）：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 scripts/machine-test.py runtime --case D15-two-second-foreground
PYTHONDONTWRITEBYTECODE=1 python3 scripts/machine-test.py final_checks --case D15-cached-binder
PYTHONDONTWRITEBYTECODE=1 python3 scripts/machine-test.py final_checks --case D04-valid-manual-imei
```

相应动作会恢复它自己临时改变的档案，不等于结束整轮环境恢复。测试目录、用例期望和恢复要求继续见 TEST-MANUAL 与 DEVICE-TEST-MATRIX。
