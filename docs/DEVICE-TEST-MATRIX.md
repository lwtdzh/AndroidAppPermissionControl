# 机器伪装测试计划

本计划加入现有 TEST-MANUAL，先在专用 emulator-5584 / ScreenshotShield_API36 执行。其他模拟器和手机不操作。每条记录 APK SHA-256、Android/ABI、注入标记、进程 PID、配置版本、实际读取值或错误。没有真实可读基线的字段标为受限；合成厂商对象只记夹具通过。

0.4.11 的 hide_module_apps 单独核对：真实 UI 保存默认关闭/开启；Ruru 的 Xposed Modules 前后结果；实际应用/包/Intent 列表与直接查询；自身和普通 Settings 包继续可见；字段关闭、再次开启、机器关闭均在同 PID 恢复。该项加入共享目录后共 47 个字段，历史 46 字段测试保留原 APK 归属，不把新增字段写成历史通过。

下表是完整目录。每次修改按 [测试范围、结果复用与停止规则](TEST-EXECUTION-POLICY.md) 选择步骤，保留已有证据；不是每次修复都重新执行 D00–D18。完整 64 组合的触发条件、批量配置要求、复用证明和时间预算均以该规则为准。

| 编号 | 操作 | 必须观察到的结果 |
|---|---|---|
| D00 | 保存原 APK、各包 prefs、Vector 模块和作用域、权限、语言及系统设置 | 快照在 git 外，恢复步骤可执行 |
| D01 | 升级 0.3.1；首次进入未配置应用 | 六项状态屏蔽保留，机器伪装默认关闭 |
| D02 | 开启后取消；返回丢弃；旋转或页面重建 | 取消不保存，旋转保持草稿 |
| D03 | 使用两种预设并保存 | 型号/竖屏规格正确；两个卡槽不同；所有已选字段通过格式检查 |
| D04 | 单字段随机、手工、非法输入；整组随机 | 只更新对应/已选随机字段；IMEI 校验失败不能保存 |
| D05 | 同一进程连续读取，再保存新 IMEI / Android ID / OAID / 坐标 | 2 秒轮询看到新值；PID 不变；旧值不因普通读取自行随机 |
| D06 | 全部字段关、关闭主开关、删除档案 | 方法恢复原值/原错误；静态缓存按实际结果提示冷启动 |
| D07 | A 开、B 关、C 未配置；多进程读取；请求另一个包的 Provider | 配置互不污染；越权读/导出写拒绝 |
| D08 | Build 字段与 Java/native 三种属性读取；回调中嵌套读取另一属性 | 对应字段一致；嵌套读取不改变回调值；debug/SELinux 仍按各自开关 |
| D09 | Telephony 双卡 IMEI / SIM / CellLocation / CellInfo / 信号 | 字段开关独立；受限入口不伪称原始可读 |
| D10 | Android ID 的方法与 settings 游标；vivo/小米/MSA/指定 AIDL Proxy OAID 夹具 | 普通 settings/Provider/Parcel 不受影响；各类 ID 独立 |
| D11 | Wi-Fi / 扫描 / Java 网卡 / native getifaddrs / 蓝牙 | 合成地址格式与接口内存释放；普通回环接口不改 |
| D12 | 最后定位、Location 对象、Parcel、监听器、NMEA | 配置坐标一致；缺权限/无定位单独记录；普通对象语义 |
| D13 | 竖屏/横屏 Display、metrics、Mode；返回设置并点击 | 宽高随旋转对应；页面可操作；不更改系统 wm 设置 |
| D14 | 内存/存储/Locale/TimeZone/传感器独立开启和关闭 | 启用字段生效；其他字段与普通读写保留 |
| D15 | 检测页前台连续 2 秒采样、后台停止、重进、读取错误 | 时间更新、变化提示、字段入口明确；原状态条和日志保留 |
| D16 | 首次建立机器伪装联测基线或改变策略/共享 Hook/方法交互时，检查原有 64 种组合 | 旧屏蔽读数与普通操作对照；未来默认屏蔽规则保留；中断后补剩余或受影响项 |
| D17 | 有 native 组合的截图文件/FD、SELinux 真模式和普通文件对照 | 不出现重复 Hook 失败、EOF/错误/FD 复用异常 |
| D18 | 四 ABI 构建、Lint、签名校验；恢复全部快照并关闭专用模拟器 | 构建与运行分开记录；恢复无残留 |

D09–D12 同时保留未注入基线与明确命名的合成测试夹具。没有服务的 AOSP 模拟器不能确认真实 vivo / OPPO / 小米服务；这部分需要后续真机授权与针对 ROM 的测试。

执行器为 scripts/machine-test.py。初次执行 capture 后再 prepare，原始快照禁止覆盖；后续构建更新用 install，不重新随机或清空无关档案。smoke、ui、runtime 按选择的步骤检查设置与读数。regression 复用现有 SELinux/native 执行器，仅在需要完整组合时执行；其嵌套用例接受外层 --case 筛选，定向执行保留夹具供续跑。events 对真实 SystemUI 保存和两种截图回调做关闭、开启、重新关闭对照，只删除这次生成的媒体 ID。final_checks 通过 UI 检查合法 IMEI 同 PID 更新，批量关闭全部字段并比较 46 个原值/原错误、属性及 PID，最后恢复原档案。restore 在最终结束或明确取消测试时恢复原快照，再 adb unroot 和关闭专用 AVD。失败时保留报告，--case 可定向重跑；已通过的相同 APK 用例原样保留。

shared/test/DeviceFieldTest.java 是独立 JVM 格式检查：生成的 IMEI 必须通过校验位检查，MAC 必须是本地管理单播；检查数字范围、非有限坐标、UTF-8 字节长度和非法时区。debug 夹具另查档案 schema、白名单默认关闭、空选择集合与无效 IMEI 文档。它们与真实系统接口测试分别记结果。

D15-cached-binder 关闭机器伪装后调用真实电话接口，确认电话读取来自同包辅助 PID、结束辅助进程后主进程没有遗留电话 Binder 请求；进入桌面等待系统缓存冻结，至少越过此前失败的重试时间，再返回检测页核对 PID 不变。电话超时必须显示错误，不能拿保存值代替真实读数。D06-all-fields-off 保留同 PID 还原 46 个字段的实际断言，批量保存空选择集合和原档案的执行器调整见执行规则。

构建及签名后运行 scripts/audit-machine.py，核对正式 APK 的四 ABI、五个原生库的导出符号、升级签名、Lint 和调试夹具排除情况，并记录实际 SHA-256。最终安装/相关行为对照、构建检查和恢复记录须对应交付 APK；复用结果保持原 APK 哈希并附构建时源码、环境和本次集成对照。自动计时证据中不能重新启动检测页。scripts/package-machine.py 和 finalize-machine.py 共用 test_evidence.py 审查实际结果或有完整证明的复用；原快照和最终恢复单独核对。
