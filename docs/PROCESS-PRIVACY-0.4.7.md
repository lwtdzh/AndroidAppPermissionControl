# 0.4.7：机型开关、属性读取与证明请求

本版在既有 Vector APK 中完成进程内能处理的文件读取、原始系统调用、模块自身代码读取和证明请求标识控制。屏幕参数并入“机型与系统”，这一节默认关闭。首次开启机器伪装只模拟设备标识和无 SIM 卡；机型、系统和屏幕保持真实读数。未增加外挂模块，未修改系统属性文件、系统服务或真实硬件。

无法保证淘宝、拼多多登录成功，当前没有这两款应用的登录实测。下面将实现和仍能读到真实信息的位置分别列出。

## 机型与屏幕一起开关

DeviceProfile 增加 modelEnabled，默认 false。width、height、density 改为 model 分类；读取需要机器总开关、机型总开关和字段选择同时开启。指纹派生属性和证明请求中机型标签的处理均使用同一个 get()，不会在机型关闭时继续套用预设。

旧档案缺少 modelEnabled 时按关闭处理。填写值和选中的字段保留，更换预设、统一刷新、草稿保存和页面重建都保留开关选择。关闭这一节恢复真实读数，不清空参数。位置开关仍独立，网络默认无 SIM 卡，Wi-Fi、蓝牙和其他环境项目不随首次开启机器伪装自动生效。

“小米 14”和“vivo X200 Pro mini”仍作为可选择的机型档案。首次生成档案不代表机型伪装已经启用。显示参数可能改变应用布局，需要时才开启并检查目标应用。

## 直接属性区：文件路径已处理，旧缓存页仍有限制

调用链为目标应用 → libc 或原始系统调用 → 本进程文件/系统调用适配 → 只读属性快照。

shared/native/property-area.h 按 Bionic 属性区布局处理 trie、prop_info、serial、普通值和长值偏移。对选中的 ro.* 生成一致的属性值与对象头部，清除旧值及长值残留；保留未选择属性。对偏移、长度、终止符、环路和容量进行检查。

devicestate 保留应用原文件描述符，read/pread/readv/preadv2 读取原文件后只覆盖变化字节。原 FD 的访问模式、独立打开的位置及错误返回保留。只读 mmap 使用密封模块文件的 MAP_PRIVATE 映射；写入共享映射不会被借机变成可写私有文件。

device-syscall-view.h 使用 seccomp user-notification，TSYNC 同步已存在的线程。代理线程在同步过滤器前完成 ready 握手，以免初始化自身进入过滤器等待；回调使用预先准备的快照和隐藏 raw syscall 指令进行 I/O，避免代理通知自己。关闭档案后过滤器继续存在，代理放行普通调用。no_new_privs 和 seccomp 状态可被观察，因此这一层不是不可见的注入。

ARM64 实测覆盖普通 libc 和内联 SVC 的新 FD、已缓存 FD、read 与只读 mmap；开关更新在原 PID、原工作线程完成。新增 readv/preadv2 检查包含 offset=-1 的当前位置语义。i386 旧 mmap 的六个参数在指针指向的结构中，本版按该结构解码并复制，不改写调用者参数。四 ABI 编译通过，运行证据限于 Android 16 ARM64。

已经缓存的 CPU 映射不一定调用函数或系统调用。模块尝试重映射能够安全隔离的只读页，并在更新/关闭时恢复原始共享映射；全局 serial、dirty backup、共享可变属性所在页以及装不下新长值的旧槽保留原页。

I01 长指纹夹具的结果是 remappedPages=0、retainedPages=3，cachedAreaSubstituted=false。最终 I07 短值夹具观察到 remappedPages=3、retainedPages=4，说明能够隔离的页确实会被替换，但 I07 没有重新验证旧 CPU 缓存页。I01 的缓存页仍是未覆盖项，不能把文件 read/mmap 通过算成它通过。

原因是内核以页建立映射，同一页可能同时包含需替换的只读值和其他系统持续更新的属性。用固定快照替换整页会丢失系统原有共享更新、serial/futex 和 dirty backup 语义；直接修改原共享页则会影响系统及其他进程。当前实现只在这些语义能够保留的页上替换。

这并不表示任何缓存 CPU 读取都无法改写。逐指令翻译或受控运行时可进一步拦截明确的读取代码；当前 APK 没有控制目标任意指令执行的权限。对于与模块处在同一权限级别、能直接读取映射、检查/修改信号处理器、跳到允许的 syscall 指令或重新取得映射的任意代码，进程内 Hook 不能建立可信隔离。要保证任意直接加载都看不到原值，需要进程外的内核/虚拟化隔离及共享属性语义支持。不能用“难”来代替这个权限和页映射原因。

## 代码校验：读取自身 Hook 原字节，执行页保持当前代码

shared/native/code-view.h 在本 APK 的 native Hook 成功安装时记录原字节与修改后字节。经 /proc/self/mem 的 libc/SVC 读取时，匹配到仍由本模块安装的字节才替换为原字节；后续第三方修改继续可见。shield 文件适配器与设备层共享此处理，截图开启时的组合检查已通过。

本次实测经 /proc/self/mem 读取的 __system_property_find 与磁盘 libc 原字节一致，同时直接执行页上的字节仍为 Hook 后内容。这是处理特定读取入口，不是所有代码校验不可见。

直接 CPU 数据加载和执行指令访问同一个映射页。普通进程页表没有“取指返回 Hook 字节、数据加载返回原字节”的逐字节双视图。本模块也无法禁止同进程代码检查自己的指令、映射、加载库、过滤器或处理器。因此，任意内联哈希、未知校验代码和任意注入检测不能由本 APK 通用保证。受控指令翻译或更低层执行隔离需要模块当前不拥有的执行控制；单独改 libc 读取函数不能获得这种能力。

本版只处理本模块成功安装的 Hook，不能替未知加固库或第三方模块伪造所有校验结果。已有外部入口跳转继续保留，避免加固冲突。

## 硬件证明：减少个人标识，保留真实密钥与签名

调用链为应用密钥生成 → Keystore/KeyMint 请求参数 → 本模块复制参数并移除已选择的标识标签 → 原 Keystore/TEE 路径。

AttestationPrivacy 与 AttestationHooks 处理 KeyMint/Keymaster 类型化标签，按实际生效字段移除设备标识、机型字段及适用的 unique ID 请求。不会修改调用者原数组/列表，不修改 challenge、密钥用途、授权条件、真实证书或证书链签名。

本次真实 EC 密钥生成、签名与验证通过。带 challenge 的证明请求生成了三张证书，challenge 匹配、链内签名保持，移除五个已选择机型标签。未移除这些字段的基线请求返回 CANNOT_ATTEST_IDS，原结果保留。模拟器链的 trustedRootVerified=false；链内自洽不能代替外部可信根验证。

要让服务器认可“另一台真实设备”的证明，需要另一设备持有且外部根信任的证明密钥、正确证书链及针对服务器 challenge 的签名。密钥位于 TEE/StrongBox 或受保护的证明服务，本进程无法导出或替换这些密钥；改证书内容会破坏签名，自签链不能得到服务器信任。Vector APK 不能制造这种证明，也不能修改服务器信任根。

如果应用强制要求证明中出现这些标识，移除标识可能导致其拒绝请求。本版提供标识最小化，不能承诺同样满足该应用的身份要求。

## 服务器风控：本地输入可减少，远端记录与决定不由 APK 控制

既有标识、网络、位置开关以及本版的证明标识处理减少明确接口中的本地信息。默认保留真实机型和屏幕，也减少了机型与实际显示参数不一致的情况。

服务器仍能使用公网 IP、账号、历史设备记录、请求节奏、支付/登录历史及服务端密钥和规则。客户端收到拒绝结果后改成本地“通过”，不会改变服务器数据库、挑战验证或后续接口授权。未知协议的签名、绑定 challenge 和加密数据也不能通过通用字符串替换安全改写。

官方 Play Integrity 的 nonce/requestHash、后端决策和服务器存储记录说明了这类服务的权限结构；这里没有把它当成淘宝、拼多多使用该服务的证据。具体商业应用的服务端规则没有可验证资料或本次登录证据，报告不推测其具体命中原因。

## 当前框架不注入的进程

本 APK 的 Hook 仅在 Vector 实际注入后存在。被框架排除的隔离进程、未注入子进程或系统服务不会自动获得本模块的配置和读取视图。缺少进入该进程的执行点时，增加本 APK 内的函数不会让代码在那里运行，需要框架提供相应注入支持。硬件证明和远端判定也不能靠增加同权限的外挂模块保证通过。

verification/incremental-0.4.7-results.json 保留每个用例的原 APK 哈希和实际观察；源文件快照在 verification/build-inputs.json。旧用例未重复执行，不把旧 APK 结果改写成最终 APK 的重新测试。

| I01 | 原 PID/线程上的长值、新/缓存 FD、libc/SVC read/mmap、代码读取、普通文件 |

14 个上述增量场景通过。I00–I06 在本轮较早构建上完成并保留原哈希；G00–G02 在新增边缘检查前的构建完成；G03–G05 和 I07 使用最终模块。代理初始化问题修复后只补测受影响组合，未重跑已通过属性路径。最后的源代码改动为 i386 旧 mmap 和 preadv2 偏移修复，最终 ARM64 边缘检查覆盖其共同代理路径；i386 为编译证据。

ModelGateTest 的 126 项新增断言已运行一次并通过，原日志保留。属性区/代码视图的 sanitizer 检查及 2000 次结构变异在本轮前段完成，后续未修改这两个共享头文件，也未重复执行；本交付没有将阶段摘要冒充该检查的原始 stdout。

最终正式 APK 四 ABI、84 项模块符号检查、外部签名身份及调试 Java/native 夹具排除通过，release lint 无 Error/Fatal。调试入口不在正式验证器内。设备验证使用专用 emulator-5584，未部署到 vivo；模拟器的原设置、原模块作用域及包状态在结束时恢复。
