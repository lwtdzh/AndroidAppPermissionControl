# 动卡空间启动兼容 · AppStateShield 0.2.1

vivo V2419A（Android 16 / ARM64，Vector 2.2）上的动卡空间 11.22.6，在五项全开时已连续三次进入实际首页。每次用时约 6.88、6.24、6.43 秒，均无 VPN、代理或开发者提示。系统实际 VPN 的 `tun0` 仍在，测试没有关闭用户 VPN，也没有执行登录或金融业务。测试后恢复原来的默认配置与五个作用域条目，其他应用的配置没有改变。

## 原因与修改

0.2.0 全开时停在启动阶段，关闭截图屏蔽能继续启动。真机读取确认，在模块安装截图 native Hook 前，`open` 已是 `LDR X16, [PC+8]; BR X16` 跳转入口。单独替换 `open` 会失败，单独替换 `readlink` 或 `syscall` 能进入首页；把路径判断直接放行仍会失败。保留原来的跳转后恢复启动，说明这里是已有加固 Hook 与再次替换入口的冲突。

0.2.1 在 ARM64 检查两种入口：外部 `B`，以及 16 字节 literal `LDR/BR`。已有跳转到其他库或匿名代码时保留该入口，其他函数继续安装。先排除本模块已经安装的别名，避免把自己的跳转记成应用已有的 Hook。未增加包名名单，策略、五项开关和 `Application.attach` 前的安装时机保持原样。

最终真机截图 native Hook 数量为 27。已有跳转的符号（包含同地址别名）为：`__open_2`, `__openat_2`, `mmap`, `mmap64`, `open`, `open64`, `openat`, `openat64`, `pread`, `pread64`, `read`。VPN native 为 2，调试 native 为 3。三次启动都读取到 `Policy loaded=true`，启用方法为 screenshot、vpn、proxy、developer、debug。

## 限制

被保留的原生入口没有完整截图屏蔽，动卡空间通过这些路径读取截图文件仍可能成功。首页正常、开关开启、Java 读取受保护和 native 库加载成功都不能证明这些入口被屏蔽。Java 层和其他成功安装的原生 Hook 继续工作；动卡空间自身的每一种截图读取路径未逐项验证。

入口识别仅覆盖上述两种 ARM64 形式。其他加固方式、其他 ROM、其他 ABI 的实际启动未验证。四 ABI 编译通过不能替代实机结果。SELinux 仍未实现，无线调试开启基线也仍未建立。

剪贴板构造检查在自身 `finally` 中恢复原对象；本次针对启动的检查没有独立记录测试前剪贴板对象指纹，因此没有把它计作独立验证通过项。真机没有执行剪贴板测试。
